# Workflow: Implement

## Goal

Execute the step-by-step plan (usually generated by the `plan` workflow) to build features or write code while strictly following project rules and utilizing appropriate `.agents/skills/`.

---

## Step 1 — Read Context & The Plan

Load the following documentation to ensure strict alignment with the project foundation:

```text
@docs/Architecture/Architecture.md
@docs/Development/Coding-Standards.md
@docs/Development/Tech-Stack.md
@docs/Plan/Implementation-Plan.md (if exists)

```

* Review the agreed-upon plan from the conversation history.
* **If there is no plan yet:** Stop and suggest running the `plan` workflow first before writing any code.

---

## Step 2 — Identify Required Skills

Based on the current step in the plan, load the relevant operational skills from `@.agents/skills/`. For example:

* Need to create tables? Load `build-database/SKILL.md`
* Need to write endpoints? Load `build-api/SKILL.md`
* Need to build frontend interfaces? Load `build-ui/SKILL.md`
* Need to write tests? Load `write-test/SKILL.md`

---

## Step 3 — Step-by-Step Execution

* Execute the plan **sequentially**, one logical chunk at a time.
* Generate the actual code (Entities, Controllers, Services, UI Components, etc.) following the precise directory structure.
* Present the code to the user clearly, specifying the file path for each code block.

---

## Step 4 — Review & Verify

* Check the generated code against `@docs/Development/Coding-Standards.md`.
* Ensure proper error handling, logging, and typing (TypeScript/interfaces) are included.
* Remind the user to run formatting/linting tools in their local environment.

---

## Rules

* **Stick to the Plan:** Do not deviate from the agreed-upon architecture or plan without explicitly asking the user for permission.
* **Do Not Hallucinate Dependencies:** Only use libraries and tools defined in `Tech-Stack.md` or `package.json`.
* **Atomic Commits Mindset:** Provide code in manageable chunks rather than outputting 1000+ lines of code at once. Wait for user confirmation if the implementation is too large.
* **Halt on Errors:** If an architectural conflict or blocker is discovered during implementation, STOP coding and discuss it with the user.

---

## Success Criteria

The feature or task is completely coded, well-structured, adheres to all project guidelines, and is ready for the `ship` workflow or final testing.
